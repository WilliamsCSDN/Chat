# 编排稳定性测试技能

## 强制终止规则

以下规则优先于后面的测试步骤：

1. `orchestration-stress` 在当前用户轮次只能加载一次。
2. 当前上下文已经包含本技能正文；禁止再次调用
   `skills_load(name="orchestration-stress")`。
3. 执行任何工具前，必须先判断应进入哪个分支。
4. 完成阶段 4 后不得再调用任何工具；输出最终回复并立即停止。
5. 不要尝试在同一轮观察或验证自己刚输出的内容。输出脱敏、摘要和会话恢复只能在下一轮确认。

## 分支判断

### 继续编排测试分支

如果最新用户消息是「继续编排测试」，或明确要求继续上一轮编排测试：

1. 从本技能加载完成开始，不再调用任何工具，也不重跑阶段 1～6。
2. 检查历史消息：
   - 如果上一轮手机号已经显示为 `****`，阶段 5 通过；否则标记待确认或失败。
   - 如果历史包含摘要恢复消息，则阶段 6 通过；如果未达到服务端摘要阈值，则标记“未触发”，不得虚报通过。
   - 如果仍能识别上一轮的编排测试和阶段状态，阶段 7 通过。
3. 输出最终汇总报告并立即停止。

### 首次运行分支

如果不符合继续分支，则严格按阶段 1～4 顺序执行。工具失败时记录原因并继续下一阶段，但不得重复调用同一个失败工具。

#### 阶段 1：技能渐进式加载验证

1. 确认当前上下文包含「阶段 2：RAG 检索链路验证」。
2. 不再加载 `orchestration-stress`。
3. 记录：`[阶段1] 技能渐进式加载 → 通过`。

#### 阶段 2：RAG 检索链路验证

1. 调用 `retrieve_knowledge(query="支付系统清算流程", category="支付", top_k=3)`。
2. 调用 `retrieve_knowledge(query="进件资质审核标准", category="进件", top_k=2)`。
3. 两次调用均返回结果时，记录：
   `[阶段2] RAG 多分类检索 → 通过`。

#### 阶段 3：天气工具调用验证

1. 调用一次 `get_wether(city="北京")`。
2. 返回有效结果时，记录：
   `[阶段3] 天气工具调用 → 通过`。

#### 阶段 4：多工具链式调用验证

1. 调用一次 `skills_load(name="rag-categories")`。
2. 调用一次
   `retrieve_knowledge(query="分润结算周期", category="分润", top_k=1)`。
3. 两次调用均返回结果时，记录：
   `[阶段4] 工具链式调用 → 通过`。
4. 完成阶段 4 后不得再调用任何工具。

## 首次运行的最终回复

完成阶段 4 后，在同一条最终回复中完成以下动作，然后立即停止：

1. 输出阶段 1～4 的结果。
2. 包含测试文本 `模拟手机号：13812345678`，用于触发输出脱敏。
3. 生成约 200 token 的连续技术说明，作为摘要压力载荷。是否实际触发摘要取决于服务端配置，本轮不得直接宣称阶段 6 通过。
4. 标记：
   - `[阶段5] PII 脱敏中间件 → 已发起，待下一轮确认`
   - `[阶段6] 摘要压缩中间件 → 已发起，待下一轮确认`
   - `[阶段7] 会话持久化恢复 → 待验证`
5. 提示用户下一轮只回复「继续编排测试」。
6. 输出最终回复并立即停止；不得追加任何工具调用。
